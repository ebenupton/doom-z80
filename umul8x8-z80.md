# Quarter-square umul8x8 is worth porting to Z80, but at 1.7x rather than 5x

All figures are T-states, inline, excluding call and return. Byte counts are for the inline code body.

## Baseline: shift and add is competitive on Z80

The 6502 has no cheap 16-bit shift, which is why table lookup wins there by roughly 5x. The Z80 does: `add hl,hl` shifts sixteen bits in 11T, and the multiplier can be seeded in H so that its top bit falls into carry on the same instruction that shifts the partial product up into L.

```
        ld   d,0        ; 7     E = multiplicand, H = multiplier
        ld   l,d        ; 4
        add  hl,hl      ; 11    unrolled x8
        jr   nc,$+3     ; 12 taken / 7
        add  hl,de      ; 11
```

23T or 29T per bit, so 184–232T for the eight bits plus 11T of setup. **~220T average, 35 bytes, no tables.** That is the number any table method has to beat.

## Straight port of the four-table form

Tables `sq1` (f(x) for x in [0,510]) and `sq2` (f(x-255)), each split into low and high byte halves, four 512-byte tables in a 2KB aligned block. `cpl` replaces the 6502 `EOR #$FF`.

```
        ld   a,b        ; 4
        add  a,c        ; 4     s = b+c, carry is bit 8
        ld   l,a        ; 4
        ld   a,sq1>>8   ; 7
        adc  a,0        ; 7
        ld   h,a        ; 4     30
        ld   e,(hl)     ; 7
        inc  h          ; 4
        inc  h          ; 4     +$200 to the high table
        ld   d,(hl)     ; 7     22   DE = f(b+c)
        ld   a,c        ; 4
        cpl             ; 4
        add  a,b        ; 4     b-c+255
        ld   l,a        ; 4
        ld   a,sq2>>8   ; 7
        adc  a,0        ; 7
        ld   h,a        ; 4     34
        ld   c,(hl)     ; 7
        inc  h
        inc  h          ; 8
        ld   b,(hl)     ; 7     22   BC = f(b-c+255)
        ex   de,hl      ; 4
        or   a          ; 4
        sbc  hl,bc      ; 15    23
```

**131T, 29 bytes, 2KB of tables.** Table generation runs on second differences (f(x+1) - f(x) = floor((x+1)/2)) at roughly 40T per entry, so about 20,000T, or 6ms at 3.5MHz.

The 1.7x margin comes down to pointer synthesis. The Z80 pays 18T per nine-bit index to fold the carry into H, where the 6502 gets `lda tab,x` for four cycles. Any variant that removes the nine-bit index is therefore the place to look for gains.

## Variants worth taking

**Mirror the difference table.** f is even, so the second term only ever needs f(|b-c|), an eight-bit index into the low half of `sq1`. H is then constant and `sq2` disappears entirely.

```
        ld   a,b        ; 4
        sub  c          ; 4
        jr   nc,$+4     ; 12 / 7
        neg             ;      8
        ld   l,a        ; 4
        ld   h,sq1>>8   ; 7    no carry propagation
        ld   c,(hl)     ; 7
        inc  h
        inc  h          ; 8
        ld   b,(hl)     ; 7
```

53–56T against 56T for the branchless index, so speed is a wash and the gain is space: **1KB instead of 2KB, ~128T average**, with 3T of data dependent jitter. This inverts the 6502 tradeoff, where the four-table form wins cleanly on cycles.

**Constrain both operands to seven bits.** Then b+c is at most 254 and b-c+127 lies in [0,254], both eight-bit indices, H constant throughout, tables 256 entries each.

```
        ld   a,b / add a,c / ld l,a / ld h,t1>>8      ; 19
        ld   e,(hl) / inc h / ld d,(hl)               ; 18
        ld   a,b / add a,127 / sub c / ld l,a / ld h,t2>>8   ; 26
        ld   c,(hl) / inc h / ld b,(hl)               ; 18
        ex de,hl / or a / sbc hl,bc                   ; 23
```

**104T, 1KB.** Note that the mirror trick loses here (50.5T against 44T for the offset index), because with no carry to propagate the offset form is already cheap. Take one or the other, not both.

In fixed point rasteriser code a seven-bit constraint on one or both operands is frequently free, and this is the largest single win on offer.

**Drop the high tables where only the low byte of the product is wanted.** Common for texture coordinate stepping modulo 256. Nine-bit operands: 82T and 1KB. Seven-bit operands: 63T and 512 bytes.

**Build a per-multiplier table where one operand is loop invariant.** A 512-byte table of k.x generated by repeated `add hl,de` reduces each multiply to 22–29T. Generation costs roughly 40T per entry, so break-even against the 131T general case is around 100 multiplies sharing the same k. That does not pay per span; it can pay per sector or per frame.

## Target dependencies

- **Contended memory.** The table method makes eight more memory accesses than the shift and add loop. On a Spectrum the tables must sit above $8000 or in an uncontended bank, or the 1.7x erodes materially.
- **Amstrad CPC.** Instruction timings round up to multiples of 4T, which taxes the 7T `ld r,(hl)` reads specifically. The counts above need recomputing before any decision on that target.
- **Z180, eZ80, R800.** `MLT` and `MULUB` make the whole question moot. Confirm the target part before building tables.

## Summary

| Method | T-states | Bytes | Tables |
|---|---|---|---|
| Shift and add, unrolled | ~220 | 35 | none |
| Quarter-square, four tables | 131 | 29 | 2KB |
| Quarter-square, mirrored difference | ~128 | 31 | 1KB |
| Quarter-square, seven-bit operands | 104 | 27 | 1KB |
| Low byte only, seven-bit operands | 63 | 19 | 512B |

The recommendation is the seven-bit form if the fixed point layout permits it, the mirrored form otherwise, and a check on whether the multiply sits on the critical path at all before committing 1KB or more of table.
